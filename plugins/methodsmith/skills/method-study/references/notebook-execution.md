# Authorized notebook execution and evidence attachment

Read this when notebook execution has been explicitly authorized, before invoking `scripts/notebook_evidence.py` and before attaching a run with `record-run`. Anchor the script to the loaded skill directory as in SKILL.md.

Use `scripts/notebook_evidence.py` only for explicitly authorized execution, after checking the notebook and its imports for external writes, network use and compute cost. This helper is not a sandbox. It runs a protected copy in a fresh process/kernel, leaves source files intact, and keeps logs under a new run directory. Relative resource behavior may differ for documents that resolve paths from their own file location; inspect and supply the required project resources rather than silently changing scientific code. Missing runtimes and failed execution stay unavailable/failed. Execution-option verification requires PyYAML and fails closed if unavailable or malformed. It checks every nested option branch, including format overrides; disabled execution in an inactive branch also requires review. External metadata includes are unsupported and block verification. Only standalone Quarto documents are verified: inherited `_quarto.yml`/`_quarto.yaml` projects and profile/project environment overrides block execution before it starts. Each accepted run gets a retained isolated project configuration. Project-backed documents require separate verification rather than silently overriding their execution settings. Quarto verification disables caching and persistent kernels and requires a retained Jupyter execution notebook; allowed errors or unexecuted code cells fail verification. Quarto engines without that evidence report unavailable even if rendering succeeds; this helper does not yet verify knitr-based `.qmd` execution. Native R Markdown uses its separate adapter. Inspect all render outputs for chunk errors before recording success; a successful render alone is not proof that every intended analysis ran.

For evidence that will be attached with `record-run`, supply `--study-root`, `--study-id` and `--artifact-id` to the execution helper. It captures declared input bindings before execution and checks them again afterward; standalone runs remain incomplete and cannot be attached as current study evidence. Versioned run evidence must include typed timestamps and environment, consistent outcome/exit/coverage fields, and a hashed primary executed or rendered output. Retained run outputs are hashed and checked at attachment and status inspection. Coverage includes the full declared dependency chain; an incomplete ancestor prevents downstream approval. Missing or changed outputs invalidate freshness. Jupyter code cells tagged `skip-execution` block verification; inherited outputs are cleared only in the execution copy, and skipped cell indexes are recorded for review. Do not remove skip tags without reviewing and authorizing the additional execution.
